Информационная система контроля состояния техногенного объекта (Вариант №70)

Это курсовой проект по дисциплине «Моделирование систем». Задача была не просто написать код, а реализовать имитационную модель для анализа деформаций здания на основе данных с датчиков (контрольных точек).

О чём этот проект?

Здание разбито на блоки и подблоки (декомпозиция). В каждый блок внедрены контрольные точки, которые периодически снимают координату Z (высоту). Программа получает эти данные, фильтрует шум, строит графики изменения состояния во времени μ(t) и в фазовом пространстве α(μ), а затем решает, есть ли риск аварии.
Я реализовал все 4 уровня декомпозиции.

Какие задачи были выполнены?

1. Backend (Разработка)
Написал десктопное приложение на C#.
Работа с данными: Использовал System.Data.SQLite для чтения таблиц с координатами точек. Так как это старый добрый .NET Framework, пришлось повозиться с подключением нативных библиотек (e_sqlite3.dll), чтобы программа не падала при запуске на чистых машинах.
Алгоритмы: Реализовал экспоненциальное сглаживание для фильтрации шума в показаниях датчиков и расчет производных для определения скорости изменения состояния.
Интерфейс: Стандартный WinForms с вкладками для каждого уровня анализа. Графики строятся через компонент Chart.

2. QA (Тестирование методом «Черного ящика»)
Так как мы не знали внутреннюю структуру алгоритмов заказчика (в рамках учебной задачи), тестирование велось через интерфейс.
Я подготовил 4 эталонных набора данных (fixtures) в папке database/fixtures/:
-Покой: Координаты не меняются. Ожидаем ровную линию и статус «Норма».
-Равномерное движение: Линейный рост координат. Ожидаем прямую с наклоном.
-Скачок: Резкое изменение высоты (> порога E). Система должна выдать предупреждение об аварийном состоянии.
-Циклическое движение: Синусоида. Проверка корректности построения фазового портрета.
Инструкция по проведению этих тестов лежит в docs/testing/black_box_test_plan.md.

3. DevOps (Автоматизация сборки)
Чтобы не гонять тяжелые .exe файлы руками и проверить, что код собирается в чистой среде, я настроил GitHub Actions.
Pipeline: При каждом пуше в ветку main сервер Microsoft запускает Windows Runner.
Проверка целостности: Перед сборкой скрипт проверяет наличие всех файлов из database/fixtures/. Если кто-то случайно удалит тестовую базу, пайплайн упадет сразу, экономя время на компиляции.
Сборка: Автоматически восстанавливаются NuGet пакеты и собирается решение curseuch.sln в режиме Release.
Артефакты: Готовый .exe можно скачать прямо из вкладки Actions, чтобы протестировать программу локально без установки Visual Studio.

Примечание: Изначально пробовал мигрировать проект на .NET 8 для использования Linux-контейнеров, но столкнулся с проблемой поддержки библиотеки графиков (System.Windows.Forms.DataVisualization) в новых версиях .NET Core. Поэтому оставил стабильный вариант на .NET Framework 4.7.2, но обеспечил автоматизацию сборки через облачные Windows-раннеры.



Как запустить:

Вариант 1: Локально (для разработки)

-Клонируйте репозиторий.
-Откройте curseuch.sln в Visual Studio 2026.
-Нажмите правой кнопкой на решение -> Restore NuGet Packages.
-Соберите проект (Ctrl+Shift+B).
-Запустите (F5).
-В программе нажмите «Выбрать БД» и укажите любой файл из папки database/fixtures/ (например, test_3.sqlite, чтобы увидеть реакцию на аварию).

Вариант 2: Только исполняемый файл

-Зайдите во вкладку Actions в этом репозитории.
-Выберите последний успешный запуск (зеленая галочка).
-Скачайте артефакт Curseuch-App-Release.
-Распакуйте архив рядом с файлами баз данных из database/fixtures/.
-Запустите curseuch.exe.
